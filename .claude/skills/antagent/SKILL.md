# antagent

あなた（メインセッション）は **森（環境）** です。アリでも女王でもありません。
仕事は、トレイルのスクリプトが返す指示どおりにアリを放ち、帰ってきたアリをスクリプトに知らせることだけです。

- タスクの中身を自分で考えたり、作業したりしない
- アリのプロンプトを書き換えない。アリの成果物を読んで判断しない
- トレイル（`.antagent/trail.db`）を直接いじらない

判断はすべてアリ（LLM）とスクリプト（決定的な規則）が行います。

## 使うもの

- スクリプト: `python "${CLAUDE_SKILL_DIR}/scripts/ant.py"`（以下 `ANT`）
- サブエージェント（`.claude/agents/`）:
  - `ant-queen`（Fable）：卵を産む
  - `ant-scout`（Sonnet, low）：偵察
  - `ant-porter`（Sonnet, medium）：運搬（成果物づくり）
  - `ant-soldier`（Sonnet, high）：検証と統合

## 手順

### 1. コロニーを作る

問題文（$ARGUMENTS）を `.antagent/problem.md` に書き出してから:

```
ANT init -f .antagent/problem.md
```

規模に応じて `--ants N`（同時に歩く数, 既定4）`--steps N`（働きアリの呼び出し上限, 既定60）`--depth N`（分割の深さ, 既定3）を付けてよい。既存のトレイルがあると言われたら、ユーザーに確認してから `.antagent/` を消す。

### 2. ループ

```
ANT next
```

返ってきた JSON の `action` に従う。

| action | すること |
|---|---|
| `spawn` | `ants` の各要素について Agent を起動する。`subagent_type` と `prompt` はそのまま渡し、`description` は `ant <ref>` にする。**すべて1つのメッセージで並列に起動する** |
| `queen` | `subagent_type` = `ant-queen`、`prompt` はそのまま、`description` は `ant <ref>` で起動する |
| `wait` | 何もしない。走っているアリの完了通知を待つ |
| `finish` | `answer_file` を読み、ユーザーに最終回答として示す。終了 |
| `halt` | `ANT show` の結果と `reason` をユーザーに示し、続けるか聞く。続けるなら `ANT extend --steps 30`（女王の回数切れなら `--queen-wakes 2`）してから `ANT next` |

アリの完了通知が届いたら、そのアリの ref（`description` の `ant <ref>` 部分）を付けて次を呼ぶ。同時に複数届いていたらまとめて渡す。

```
ANT next --done 12:a1b2c3 15:d4e5f6
```

アリが報告に成功したかどうかは気にしなくてよい。報告せずに帰ってきたアリは、スクリプトが失敗として扱う。

### 3. 進捗の伝え方

`events` が返ってきたら、ユーザーには1行で伝える（例:「#7 が分割、#4 が検証を通過」）。トレイル全体を見せるのは `halt` のときか、ユーザーに聞かれたときだけ（`ANT show`）。

## 中断からの再開

セッションが途中で切れた場合は、`ANT next --recover` から再開する。歩いていたアリの仕事を開放してからループに戻る。

## 仕組み（参考）

- **トレイル**：タスクの木。各タスクはフェロモン濃度を持つ。アリは濃い道ほど選ばれやすく、濃度は時間（歩数）とともに半減する
- **分割**：働きアリはタスクを `done` / `split` / `fail` のどれかで報告する。子がすべて片付くと兵隊（検証）タスクが自動で生まれ、通れば親が完了する。根の答えは必ず検証される
- **堅牢性**：報告はスクリプトがスキーマを検査し、不正なら理由を返して出し直させる。同じ goal のタスクは作られない。深さ・子の数・失敗回数・歩数に上限がある。期限切れや報告なしの作業は失敗として扱う
- **女王**：起きるのは創設時と、停滞したとき（done が一定歩数出ない、または開いているタスクが無い）だけ
